Mesh islands — cross-framework complexity review

Post-renderer update: the React DOM worker pattern has been replicated in Vue, Svelte, Solid, and Angular via the RenderedIslandApp contract — what remains is refinement, not feasibility.

Worker renderers now exist for all four frameworks. A new RenderedIslandApp contract in defineIslandWorker — mount(ctx) → { update?, dispose? } against a realm-scoped proxy document — lets each framework's real renderer emit ops through the facade instead of touching the protocol. Vue uses createRenderer, Svelte uses the real mount()/flushSync() runtime, Solid uses solid-js/universal's createRenderer, and Angular runs createComponent over a proxy-backed RendererFactory2 with manual change detection. All four deliver fine-grained updateProps — in-place patches, not rebuilds.

Performance: the worker/main split

Measured with the driver's onOps replay-timing hook and instrumented client calls (in-process worker — transport cost excluded; real workers add structuredClone+postMessage per batch). Fixture: a 200-row tree, each row = element + class + dataset attr + text + button + listener.

React mount — 200 rows13.65.4200328%Warm mount: reconciliation + serialization ≈ 2.5× the replay cost.

React click → setState commit1.4~023%Dispatch round-trip adds ~1–4ms latency per interaction vs a main-thread handler.
Overall measured JS split: ~86% worker / ~14% main. Main-thread JS scales with op COUNT, not tree size — a 5000-vnode diff that produces 12 mutations costs the main thread ~nothing while the worker does the whole diff. The browser's layout/style/paint cost is unchanged and inherent to any UI; what the architecture removes from the main thread is the framework compute (reconciliation, reactivity bookkeeping, app logic) plus it makes forced synchronous layout reads impossible by construction. Costs that remain: one postMessage round-trip per event (~1–4ms), no preventDefault (the real event dispatched already), duplicated node bookkeeping in memory (proxy nodes + real DOM), and structuredClone of each op batch (scales with batch size, not tree size).

Dev-experience friction points

  1. Two entry points still confuse: defineIslandWorker (registry) vs defineRealmWorker (1:1) is powerful but forces an early architectural decision — and now each framework adds its own define*IslandWorker sugar on top. Consider making the registry the default and deriving 1:1 helpers automatically.
  2. React shell API is still wide: Island, islandComponent, lazyIsland, IslandShellProps, containerProps. Each new framework binding replicates a similar surface unless abstracted further.
  3. Slot semantics differ: React portals, Vue teleport, Svelte slots, Solid portals, Angular CDK portals. The worker only knows data-mesh-slot; the shell binding must bridge to the host framework.
  4. Ambient realm resolution is heuristic: out-of-task renders (Vue's microtask flush, Svelte $effects, timers) resolve their document via last-touched/last-active realm. Correct for the one-realm-per-worker norm and inside tasks, ambiguous if multiple realms' async work interleaves in one module.
  5. Geometry is a constant caveat: ResponsiveContainer-style measurement does not work in the worker. Every framework binding must document passing measured dims as props.

Refinement round 1 — landed

  1. Proxy-DOM primitives promoted. ProxyComment/createComment, comment-preserving innerHTML, kind-aware cloneNode, before/after/replaceWith/append/prepend/replaceChildren, nodeName, namespaceURI/*AttributeNS, template.content, importNode/baseURI, global Node/Text/Comment/HTMLMediaElement/customElements shims, and this-bound handlers with synthesized composedPath() all live upstream now — svelte-island/worker shrank 634→340 lines.
  2. Protocol gaps closed. mergeStyle routes --* and kebab keys to setProperty, !important crosses as a value suffix; listen/unlisten carry {once,passive,capture} with worker-side once auto-detach; the attr op clears reflected boolean properties on removal.
  3. vitest solid-js alias fixed (exact-match + server.deps.inline) — vendored universal.js deleted for the real import; JSX authoring path documented in the solid-island README.
  4. Angular deepened — 14 tests across projection, DI, lifecycle, control flow, pipes, host bindings, model(), @defer (immediate), and a hand-written static ɵcmp proving the no-compiler AOT path. Core fix: factory wrapping registers JIT-invisible signal inputs so nested components get real bindings, transforms, and ngOnChanges.
  5. Ambient realm + listener options — getLastActiveRealm exported; Vue prefers it. Once/passive/capture land on real listeners; Vue modifiers and Angular's ListenerOptions both flow through.
  6. Perf instrumentation — mountIsland({onOps}) reports per-batch replay ms; packages/worker-dom/test/islandPerf.test.ts measures the split (~86% worker / ~14% main JS) and stays in the suite as a regression backstop for op counts.

Next steps of refinement

  1. template.content direct appends emit no ops — the fragment view shares the element's shadow children under a phantom id, so content.appendChild never reaches the wire. The documented innerHTML→cloneNode flow is unaffected; fix only if a library appends to .content directly (would need driver-side routing of template-children into .content).
  2. Angular remaining surface — input({alias}) is undiscoverable under JIT (bind by field name); @defer non-immediate triggers, plain effect() assertions, forms/ngModel, animations (no driver), content queries unexplored. Sanitizer is passthrough — worker output is unsanitized.
  3. Ambient-realm determinism — out-of-task renders resolve via last-active/last-touched realm; fine for one-realm-per-worker, ambiguous under interleaved async flushes across shared-client realms. Options: require runInRealm around worker-initiated work (documented), or a proper async-context channel.
  4. Solid phantom-node caveat — el.textContent= creates shadow-only children; mixing raw textContent writes with insert()-managed children can drift the two trees. Compiled JSX only uses insert(); document the authoring convention.
  5. Vue remaining surface — v-once/static content (insertStaticContent host op unimplemented), onUpdate:* model listeners skipped, Teleport-into-island slots untested.
  6. Event latency / capability limits are structural — every interaction is one postMessage round-trip (~1–4ms); preventDefault can never work (event already dispatched). High-frequency input (mousemove/wheel/scroll-driven work) is the workload to avoid putting behind islands; document guidance.
  7. Dogfood + docs — add a non-React component island to the examples app; document RenderedIslandApp as the public extension point; keep mountIsland canonical. Geometry caveat (measured dims as props) applies to every renderer equally.
