Mesh islands — cross-framework complexity review

Post-renderer update: the React DOM worker pattern has been replicated in Vue, Svelte, Solid, and Angular via the RenderedIslandApp contract, and three refinement rounds since then closed the protocol gaps, promoted the shared proxy-DOM primitives, and removed the worst setup footguns — what remains is refinement, not feasibility.

Worker renderers now exist for all four frameworks. A new RenderedIslandApp contract in defineIslandWorker — mount(ctx) → { update?, dispose? } against a realm-scoped proxy document — lets each framework's real renderer emit ops through the facade instead of touching the protocol. Vue uses createRenderer, Svelte uses the real mount()/flushSync() runtime, Solid uses solid-js/universal's createRenderer, and Angular runs createComponent over a proxy-backed RendererFactory2 with manual change detection. All four deliver fine-grained updateProps — in-place patches, not rebuilds.

Performance: the worker/main split

Measured with the driver's onOps replay-timing hook and instrumented client calls (in-process worker — transport cost excluded; real workers add structuredClone+postMessage per batch). Fixture: a 200-row tree, each row = element + class + dataset attr + text + button + listener.

ScenarioWorker msMain msOpsMain shareTakeaway
Imperative mount — 200 rows11811.626039%First mount includes module init; replay is a one-time DOM-construction burst.
Imperative updateProps — full rebuild4.46.4260459%The worker rebuild is cheap so replay dominates — the strongest argument for renderer-backed fine-grained updates over rebuild semantics.
Imperative click dispatch1.40.126%Steady-state interactions are nearly free main-side.
React mount — 200 rows13.65.4200328%Warm mount: reconciliation + serialization ≈ 2.5× the replay cost.
React updateProps — diffed patch13.40.78015%Diffing cost stays in the worker; 200 changed cells cost the main thread under a millisecond.
React click → setState commit1.4~023%Dispatch round-trip adds ~1–4ms latency per interaction vs a main-thread handler.
Overall measured JS split: ~86% worker / ~14% main. Main-thread JS scales with op COUNT, not tree size — a 5000-vnode diff that produces 12 mutations costs the main thread ~nothing while the worker does the whole diff. The browser's layout/style/paint cost is unchanged and inherent to any UI; what the architecture removes from the main thread is the framework compute (reconciliation, reactivity bookkeeping, app logic) plus it makes forced synchronous layout reads impossible by construction. Costs that remain: one postMessage round-trip per event (~1–4ms), no preventDefault (the real event dispatched already), duplicated node bookkeeping in memory (proxy nodes + real DOM), and structuredClone of each op batch (scales with batch size, not tree size).

Dev-experience friction points

Resolved across refinement rounds 2–4 — the connectIslandWorker+`mountIsland` two-call boilerplate (worker shorthand); props dying as a bare DataCloneError (named-key-path preflight); Solid's silently-frozen SSR build (mount-time probe); missing Angular/Vue stamp helpers and emit re-exports; stale e.target.value in handlers (form state now stamps the proxy target); the manual setMode('push') ritual (auto-subscribed at mount — the doc's earlier "call after all mounts" ordering is gone); a hard COOP/COEP requirement for poll-only users (mode:'poll'/doorbell:false); mount hanging forever on silent worker entries (mountTimeout); absent per-framework READMEs; and the unpackaged test harness — InProcessWorker is now a supported export at @jwhenry123/mesh/sdk/testing/inProcessWorker (all 30 in-repo consumers migrated); plus callbackProp(fn) marshalling — function props now cross as emit-backed callables (fire-and-forget), closing the "props are data-only" gap.

What remains open:

  1. Two entry points still confuse: defineIslandWorker (registry) vs defineRealmWorker (1:1) is powerful but forces an early architectural decision — and now each framework adds its own define*IslandWorker sugar on top. Consider making the registry the default and deriving 1:1 helpers automatically.
  2. React shell API is still wide: Island, islandComponent, lazyIsland, IslandShellProps, containerProps. Each new framework binding replicates a similar surface unless abstracted further.
  3. Slot semantics differ: React portals, Vue teleport, Svelte slots, Solid portals, Angular CDK portals. The worker only knows data-mesh-slot; the shell binding must bridge to the host framework.
  4. Ambient realm resolution is heuristic: out-of-task renders (Vue's microtask flush, Svelte $effects, timers) resolve their document via last-touched/last-active realm. Correct for the one-realm-per-worker norm and inside tasks, ambiguous if multiple realms' async work interleaves in one module — now documented as a contract (runInRealm for worker-initiated work), though a real async-context channel would be the structural fix.
  5. Geometry is a constant caveat: ResponsiveContainer-style measurement does not work in the worker. Every framework binding must document passing measured dims as props.
  6. The worker-entry incantation is bundler folklore (surfaced by the Vue dogfood): new Worker(new URL('./x.worker.ts', import.meta.url), {type:'module'}) works in Vite/webpack but each bundler has its own idiom — per-bundler setup snippets now live in the worker-dom README, and a wrong path fails with a named mountTimeout error. A bundler plugin would still remove the guessing.

Refinement round 1 — landed

  1. Proxy-DOM primitives promoted. ProxyComment/createComment, comment-preserving innerHTML, kind-aware cloneNode, before/after/replaceWith/append/prepend/replaceChildren, nodeName, namespaceURI/*AttributeNS, template.content, importNode/baseURI, global Node/Text/Comment/HTMLMediaElement/customElements shims, and this-bound handlers with synthesized composedPath() all live upstream now — svelte-island/worker shrank 634→340 lines.
  2. Protocol gaps closed. mergeStyle routes --* and kebab keys to setProperty, !important crosses as a value suffix; listen/unlisten carry {once,passive,capture} with worker-side once auto-detach; the attr op clears reflected boolean properties on removal.
  3. vitest solid-js alias fixed (exact-match + server.deps.inline) — vendored universal.js deleted for the real import; JSX authoring path documented in the solid-island README.
  4. Angular deepened — 14 tests across projection, DI, lifecycle, control flow, pipes, host bindings, model(), @defer (immediate), and a hand-written static ɵcmp proving the no-compiler AOT path. Core fix: factory wrapping registers JIT-invisible signal inputs so nested components get real bindings, transforms, and ngOnChanges.
  5. Ambient realm + listener options — getLastActiveRealm exported; Vue prefers it. Once/passive/capture land on real listeners; Vue modifiers and Angular's ListenerOptions both flow through.
  6. Perf instrumentation — mountIsland({onOps}) reports per-batch replay ms; packages/worker-dom/test/islandPerf.test.ts measures the split (~86% worker / ~14% main JS) and stays in the suite as a regression backstop for op counts.

Refinement round 2 — DX, landed

  1. One-call mount. mountIsland({ worker }) builds and owns its client — the connectIslandWorker + mountIsland pair collapses for the common one-island-per-worker case. Neither given → a named error.
  2. Cloneable-props pre-flight. Mount and updateProps run a structuredClone check that names the offending key path (rows[1].render) instead of dying as a bare DataCloneError inside the pool's postMessage.
  3. Solid SSR-build probe. The silent-frozen-island footgun now throws at first mount: a signal bump must re-run an effect — the server build's createRenderEffect runs fn once and never again.
  4. Entry parity. defineAngularIslandWorker (with {component, providers} entries) + angularIsland/vueIsland stamp helpers match the svelte/solid shape; emit/runInRealm re-export from every -island/worker entry.
  5. e.target.value/.checked stamp. _enrichEvent writes the dispatched form state into the wrapped target's shadow attrs — the DOM idiom input handlers read — without echoing an attr op back. (The public setters emit ops; stamping must not.)
  6. Dogfooded: a Vue island in the demo. examples/react-dom-worker mounts vue-notes (real Vue createRenderer, worker bundle carries zero React) via the worker shorthand — typing, add, emit, and in-place patch all pass in-process E2E. Root vitest aliases now cover all four -island packages so published specifiers resolve to sources.
  7. READMEs everywhere. worker-dom documents the RenderedIslandApp contract + per-framework table; vue/svelte/angular-island ship READMEs matching solid-island's (shell API, worker entry, caveats).

Refinement round 3 — transport DX, landed

  1. Push mode auto-subscribes at mount. The setMode('push')-after-mount ritual is gone — mountIsland starts the doorbell (or the poll timer) itself once the handshake lands. Made safe by observe() re-watching when the contract rebinds: in-process harnesses bind every defined contract on each pool spawn, which used to pin the watch to a stale buffer.
  2. Islands without SharedArrayBuffer. mountIsland({mode:'poll'}) (or connectIslandWorker({doorbell:false})) builds a message-only pool — no COOP/COEP cross-origin isolation needed; setMode('push') on a doorbell-less client falls back to polling.
  3. mountTimeout bounds the handshake. A worker entry that loads but never answers (missing define*Worker, hung import) rejects with a named error at 15s instead of pending forever; failed mounts release the realm and terminate island-owned clients — which also stops a crash→respawn loop on a permanently-broken entry.
  4. InProcessWorker fidelity. Module-load failure fires error and dead workers drop tasks — tests see the crash path instead of a hang. And a real latent bug: message-only pools (INIT) never loaded the handler modules at all.

Refinement round 4 — correctness + authored docs, landed

  1. template.content direct appends emit ops. The content view now carries the template element's instance (a templated-scoped fragment), so content.appendChild reaches the wire; the driver routes template-parented append/remove ops into HTMLTemplateElement.content — the DOM-spec home for template children. Direct content mutation, anchored insertion, and the instantiation path (innerHTML → cloneNode) all verified end-to-end.
  2. Vue insertStaticContent / v-once. The host op parses static HTML through a proxy <template> and moves the parsed children into the host, returning first/last anchors — createStaticVNode (what compiled v-once/hoisted nodes produce) lands as real DOM in the island E2E.
  3. Solid's phantom-node convention documented. el.textContent= on the proxy DOM emits one utext op and records a phantom text child with no wire identity; mixing it with insert()-managed children drifts the two trees. The solid-island README now documents the convention: dynamic text goes through insert() as a real text node (what compiled JSX already emits).
  4. Packaged test harness. InProcessWorker moved to src/sdk/testing/ — reachable as @jwhenry123/mesh/sdk/testing/inProcessWorker through the existing ./sdk/* export. All 30 consumers migrated to the package specifier; worker-dom README documents the supported setup.
  5. Renderer-authoring + workload docs. worker-dom README gains a "Writing a worker renderer" guide (the RenderedIslandApp.mount → {update?, dispose?} contract, the proxy-DOM host surface, realm resolution and the runInRealm contract for out-of-task work, event semantics) and a "Workload fit" section (one postMessage round trip per event; keep high-frequency input main-thread; replay cost scales with op count — onOps measures the split).

Refinement round 5 — Vue surface + callback props, landed

  1. Vue v-model verified end-to-end. onUpdate:* prop skipping matches runtime-dom exactly — element v-model is the directive (vModelText/vModelCheckbox), whose hooks drive addEventListener + el.value/el.checked + el._assign on the proxy. Hand-compiled fixtures prove input and checkbox two-way binding round-trips; the skipped listener was never the path.
  2. Vue Teleport into the island. The renderer now answers the querySelector host op against the realm's shadow tree — <Teleport to="body"> lands content in the island root. Fixing it surfaced a real worker-dom gap: document.querySelector('body')/'html' never matched the id-0 root — a leading bare body/html compound now pins to it.
  3. callbackProp(fn) — function props cross the wire. The last common DOM idiom that couldn't. Shell-side markers marshal to {__cb:id} handles (nested containers supported); the worker unmarshals them to callables that emit on a reserved name the driver routes to the island's callback table — verified end-to-end from inside a dispatched click. Fire-and-forget by design (no await channel), doorbell-rung for out-of-task callers.
  4. Bundler worker-entry docs. worker-dom README documents the per-bundler entry patterns (Vite/webpack new URL idiom, Vite's ?worker, esbuild's separate-entry caveat) and the mountTimeout error as the symptom of an unresolved path.

Next steps of refinement

  1. Angular remaining surface — input({alias}) is undiscoverable under JIT (bind by field name; the alias isn't stored anywhere reachable — documented limitation); @defer non-immediate triggers, plain effect() assertions, forms/ngModel, animations (no driver), content queries unexplored. Sanitizer is passthrough — worker output is unsanitized.
  2. Ambient-realm determinism (structural fix optional) — documented as a contract (runInRealm around worker-initiated work); a proper async-context channel would remove the heuristic entirely for interleaved shared-client realms.
  3. Vue remaining surface — <Transition> degrades (no real getComputedStyle duration detection); Teleport to main-thread targets is structural — the slot system is the supported escape; keepalive/async-component depth untested.
  4. Two-way callback props — callbackProp is fire-and-forget; a request/response channel (worker awaits a shell result) would need a main-thread task server — bigger than the remaining value.
