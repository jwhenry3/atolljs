Islands based multithreading

Worker pools and shared workers joined to your app through one shared-memory fabric. Contracts share fixed-layout SharedArrayBuffer state across threads; work is offloaded via task commands and state reactivity.

The fabric

One contract, every thread

Worker pools

Typed task dispatch over lazily-spawned workers. Call a method, get a promise.

Shared-memory contracts

Fixed-layout SharedArrayBuffer state, declared once and identical on both threads.

Cross-thread reactivity

observe, watch, and task state subscribe on either side of the boundary.

Worker-rendered islands

Whole framework trees committed off the main thread, replayed as DOM ops.

Why atoll

Micro-frontends without the plumbing

Typed contracts

defineSharedMemory and defineIslandContract declare the wire once. Both threads type-check against it, and payloads validate at the boundary.

Any framework, or none

One op protocol carries React, Vue, Solid, Svelte, and Angular trees side by side, plus imperative proxy-DOM apps. The shell never imports another framework.

Topology per mount

Dedicated worker, shared client, or nested sub-worker: the mount call decides, the app doesn't change. The demos put all three on one page.

Remote MFEs

Worker bundles can live on another origin, versioned and cached like any asset. The contract module is the only import the host needs.

Mission: make multithreaded JavaScript feel like single-threaded JavaScript. Atoll turns the worker boundary into a typed contract: pools, task dispatch, reactivity, and worker-rendered UI islands all speak one fixed-layout shared-memory fabric. Heavy work leaves the main thread without leaving your framework's idioms: no bespoke postMessage plumbing, no serialization guesswork. Declare the contract once, and both threads speak it.
